# Authorization interface

- Preserve human Phoenix test/switch/boot as terminal `nixos-rebuild --sudo`,
  without required reasons. Bind explicit ai-broker deployment directly to immutable
  clients; never recurse through human wrappers or use an environment identity flag.
- Agents use `phoenix-authorize --task TASK --reason PURPOSE -- phoenix-test ...` or the
  closed diagnostic mapping. Reasons/task labels are bounded nonsecret context;
  installed root policy, peer checks and authentication remain authoritative.
  Preserve `ai-broker` as a compatible alias; gate naming must not alter human commands.
- Keep automatic diagnostic defaults documented by bounded-operation rationale.
  `automaticDiagnostics.enable=false` defaults to human and must reject explicit
  automatic overrides; denied decisions and deployment-review ownership stay intact.
- Future authority extensions require explicit opt-in options and dependency
  assertions; an available dependency must never automatically enable authority.
- `security-review` is routing admission, not a successful verdict: require a
  separately validated exact-bound review before execution. Preserve the diagnostic
  daemon's CAP_SYSLOG boundary; delegate protected reviewer UID/GID work to the
  existing capable controller rather than broadening diagnostic capabilities.
- Keep this adapter a thin immutable-path argv mapping into existing clients;
  reject arbitrary commands, shells, inner reason overrides and option tails.
  Do not add a daemon, PATH lookup, caller-selected policy or legacy activation fallback.
- Native explanation is experimental/default off via one `explanation.enable`
  option. Only the adapter's explicit presentation flag selects it, after matched
  root preflight; it grants no authority and must not affect ordinary Phoenix UI.
  ON cancellation/display failure stops before the unchanged authenticated helper.
- Keep one shared escaped semantic body renderer; do not capture credentials or
  UI/model stderr. Distinguish untrusted context events from root authorization.
  Source-build/stub tests do not establish live readability/focus/Polkit acceptance;
  keep exact pending review overrides independent of this generic presentation.

- Registered execution stays default OFF with no live entries until representative
  model/native-auth acceptance and explicit caller-boundary approval. Preserve exact
  immutable program/argv and current-authority rechecks before/after review; old
  helpers/cache must not revive revoked grants. Keep normal authentication and the
  explicit critical review override in distinct immutable helpers/actions.
- Test actual Nix-store objects (including sticky group-writable store boundary and
  multicall argv[0]) plus real transient cgroup cleanup; program-byte hashes do not
  establish dependency or mutable-input safety. Never broaden diagnostic capabilities
  to run the reviewer. Output/advisory rationale belong only in client responses.
